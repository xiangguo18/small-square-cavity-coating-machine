# EventDef 报警连接与验收

## 直接使用

默认启动会连接 `opc.tcp://192.168.0.10:4840`，不需要手工填写 Namespace 或 NodeId 模板。报警与IO保持只读；参数单项写入见 [IO与参数接入说明](equipment-integration.md)。

点击任一主功能页面左下角的 PLC 状态区域，打开连接设置弹窗：

1. 输入完整 Endpoint，例如 `opc.tcp://192.168.0.10:4840`。
2. 点击“保存并连接”。程序停止旧订阅，保存地址，然后连接新地址；无需重启。
3. 弹窗保留连接状态及失败原因。连接失败时保留刚保存的地址，默认每5秒重试。
4. “取消”丢弃尚未提交的输入。未登录用户也可修改连接地址。

配置位于 `%LocalAppData%/SmallSquareCavityCoatingMachine/alarms.opcua.json`。没有配置时使用上述默认地址；通过界面保存后，重启读取保存值。文件以临时文件原子替换方式保存。写入失败不切换目标，旧订阅保持停止，弹窗提示保存失败。

## 已确认的PLC通讯约定

- 匿名身份、`SecurityMode=None`、`SecurityPolicy=None`。不需要账号和客户端证书，不自动改用其他安全方式。
- 此模式不加密，仅在可信设备网络使用；它不代表可以公开到互联网。
- 服务器在 Objects 下公开一个可浏览、可读、BrowseName严格为 `EQ_Alarm` 的一维数组。
- 元素为Boolean或整数，`true/1`触发，`false/0`恢复。其他值不当作正常。
- 报警链路不提供确认或复位写入。当前统一连接显示“PLC已连接”，只开放具有参数设置权限用户的参数单项写入，不表示其他设备控制链路已接通。

旧配置若指定其他安全模式，不会悄悄降级。需要在连接弹窗明确保存新地址后，才使用本次确认的匿名无安全方式。

## 自动发现与数组绑定

服务从 Objects 递归浏览，处理分页和循环引用，通过服务器返回的NodeId定位数组，不猜测厂商前缀或固定Namespace数字。完整浏览后找不到唯一可读数组，会报“未找到”或“多个同名数组”，不随意绑定。浏览限制为60秒/50000项，超出限制同样报错而非接受不完整结果。

成功定位后主动读取一次完整数组；报警、IO、参数共用一个会话和一个订阅，各有一个数组监视项；采样请求100毫秒，发布请求250毫秒。服务端可以修订周期。

每个点位严格使用数据库地址中的真实下标：104条定义覆盖0～51及500～551，因此数组至少需要552个元素，而不是104个。程序只分发EventDef定义的下标。

数组质量异常、类型不符或空值：所有相关点位标记未知。数组过短或某个整数不是0/1：仅无效点位标记未知，其他有效点位仍然更新；弹窗显示长度及无效点数。已有报警不会因此被当作恢复。

报警链路只订阅完整数组，不使用PLC报警事件服务，不假定数组按数据库行号压缩排列。

## MVVM与生命周期

链路保持为：只读EventDef → 共享OpcUaEquipmentClient → EquipmentAlarmSignalSource适配器 → 单实例AlarmMonitorService → 历史库与ViewModel → XAML。

- PLC触发后，历史列表与全局右下角同步更新；持续触发不重复新增。
- 恢复更新同一条记录的清除时间；再次触发产生新记录。
- 首次发现已经触发的位标记“连接时已存在”，发生时间为应用发现时间。
- 断线、重连和切换Endpoint保留活动报警并标为未知；新会话收到有效数组后核对。旧会话的延迟通知不能影响新会话。
- 连接中禁用重复提交；后台通知经UI调度器更新绑定。页面卸载时关闭自身弹窗，退出应用时停止订阅并解除事件。
- 默认新地址仍代表同一台镀膜机。不要将本机报警历史当成多PLC混用的历史系统。

## 数据与历史

- 原始A盘方腔.db未修改。项目资源 `Resources/Database/方腔.db` 的SHA256：
  `ec2722d62769d52ed5a67c2d2602958b32cac76abc1aefdfaa7880dd039afb3b`。
- 首次运行按内容哈希释放到 `%LocalAppData%/SmallSquareCavityCoatingMachine/Database/方腔.definition-<hash>.db`，严格SQLite ReadOnly。
- 真实报警记录写入 `alarm-history.db`；模拟记录写入独立的 `alarm-history.simulation.db`。
- 报警记录保存失败时仍显示内存报警并明确提示；未成功落盘前退出，未保存记录可能丢失。
- 中文内容优先，Priority7显示“报警”、6显示“警告”。“空/Space”触发仍显示预留点及地址。
- 实时模式显示近7天和未恢复记录；历史模式查询后，新报警仍插入顶部，超出日期范围的标明“实时新增·范围外”。
- 所有信号均有效且正常时显示“无活动报警”；断线或无效点存在时显示“报警状态未确认”。

## 离线模拟

```powershell
dotnet run --project 'Small square cavity coating machine.csproj' -- --simulate-alarms
```

此模式不访问真实PLC，不自动制造报警；IO和参数也使用明确标记的模拟源，参数模拟写入仍需登录授权账号。进入“历史记录 → 报警记录”，使用黄色模拟面板触发、恢复、模拟断线等。模拟模式下连接弹窗只展示说明，不允许热切换到真实PLC；去掉模拟参数重新启动后才能连接真实设备。

## 测试与现场验收

```powershell
dotnet test 'Tests/SmallSquareCavityCoatingMachine.Tests.csproj'
dotnet build 'Small square cavity coating machine.csproj' -c Release
```

测试包括纯逻辑/模拟会话测试、真实WPF绑定和弹窗快照，以及仅监听127.0.0.1临时端口的真实OPC UA协议测试。测试服务器依赖只存在于测试项目，不部署到上位机产品中。测试不启动真实App，不读取用户连接配置，不访问现场PLC。

现场还需核对：网络连通、匿名无安全端点、唯一数组名称、至少552个元素、下标含义、报警有效值。按单报警/多报警/恢复/重触发/断线重连/历史范围外新增顺序验证。不要通过危险设备操作或绕过联锁制造测试报警。

收到有效通知后两处UI更新目标为500毫秒；PLC至界面的物理总延迟需现场实测。断线期间发生又恢复的短暂报警无法从当前数组重建，需要PLC锁存或事件历史能力。

OPC UA依赖与测试服务器均为[OPC Foundation官方.NET SDK](https://github.com/OPCFoundation/UA-.NETStandard)，版本1.5.378.156。
